# 에이전트 조건부 판단 비교 (Task 2)

이상치가 있는 날과 없는 날, 에이전트가 실제로 다른 툴 호출 경로를 타는지
실제 실행(Haiku, `LLM_BACKEND=anthropic`)으로 확인했다.

## 비교 요약

| | 이상치 있는 날 (2026-09-11) | 이상치 없는 날 (2026-09-21) |
|---|---|---|
| get_anomalies 결과 | KTB 3Y(z=2.15), Corp AA-(z=2.49), Corp BBB-(z=2.34) 이상치 3건 | 이상치 없음 |
| 호출한 툴 | get_market_snapshot → get_anomalies → search_news("국고채 금리") → search_news("회사채 크레딧 스프레드") → get_bond_demand_forecasts | get_market_snapshot → get_anomalies → get_bond_demand_forecasts |
| 턴 수 | 4 | 3 |
| search_news 호출 | 2회, **지표별로 다른 검색어** | 0회 |
| get_us_yields 호출 | 0회 (이상치가 한미 스프레드 쪽이 아니어서 불필요하다고 판단) | 0회 |
| 섹션 4(특이사항) | 이상치 3개를 지표별로 나열 + 원인 후보(미국 장기금리 상승) | "특이사항 없음" 한 줄 |
| 섹션 5(체크포인트) | 뉴스 기반 코멘트 | "특별한 예정 이벤트 없음" 한 줄 |
| 리포트 길이 | 길다 (조사 결과가 많아서) | 짧다 |

로그 원본: `logs/2026-09-11.jsonl`, `logs/2026-09-21.jsonl`. 리포트: `reports/2026-09-11.md`, `reports/2026-09-21.md`.

## 확인된 것

1. **이상치가 있으면 검색어가 지표 종류에 맞춰 달라진다.** 국고채 커브
   이상치에는 "국고채 금리", 크레딧 스프레드 이상치에는 "회사채 크레딧
   스프레드"로 검색했다 - 뭉뚱그린 "채권시장" 같은 검색어를 쓰지 않았다.
2. **이상치가 없으면 search_news를 아예 호출하지 않고 짧게 끝난다.** 필수
   툴 2개(get_market_snapshot, get_anomalies) + 섹션 6용 get_bond_demand_forecasts
   만 부르고 3턴에 끝났다.
3. **한미 스프레드 쪽 이상치가 아니면 get_us_yields를 부르지 않는다.** 두
   날 모두 get_us_yields를 안 썼다 (이상치가 KTB/크레딧 쪽이었어서).

## 실행 중 발견하고 고친 문제

**get_bond_demand_forecasts를 "선택"으로 분류했더니, 이상치 없는 날 첫
실행에서 이 툴을 아예 호출하지 않고 "최근 회사채 수요예측 공시 없음"이라고
근거 없이 써버렸다** (실제로는 확인도 안 한 주장 - 수치는 아니라서
verify.py도 못 잡는 종류의 환각이었다). agent/prompts.py와
agent/tools_schema.py에서 get_bond_demand_forecasts를 "섹션 6을 쓰려면
이상치 유무와 무관하게 매번 호출, 호출 없이 '없음'이라고 쓰는 것은 금지"로
명확히 재분류한 뒤 재실행하니, 실제로 툴을 호출해서 얻은 진짜 데이터로
섹션 6을 채웠다 (SK지오센트릭/대한전선/제주은행 등 5개 회차 표, Task 1의
다중 회차 지원 덕에 회사당 여러 행으로 정확히 분리됨).

부수적으로, 같은 재실행 과정에서 리포트 맨 앞에 "정리하겠습니다" 같은
서두 문장이 붙는 것도 발견해서 프롬프트에 "## 1. 한 줄 요약으로 바로
시작하라"는 지시를 추가해 없앴다 (2026-09-11 리포트에는 이 수정 전에
생성된 서두 문장이 남아있음 - 기능적 문제는 아니라서 재실행하지 않음).

이 비교를 위해 실제 브리핑 실행 4회 사용 (2026-09-11 1회, 2026-09-21
버그 발견/수정 확인용으로 3회 - 밤샘 작업 전체 8회 예산 중).
